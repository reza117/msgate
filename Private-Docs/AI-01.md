# AI-01 — Development Plan, Naming & Roadmap

> Source blueprint: `info-01.md`  
> Product concept: **SMTP → Exchange (EWS) / Microsoft Graph** gateway with smart auth sanitization, queue/retry, REST API, Web UI, and observability.

---

## 1. Concept Summary (Understood)

A lightweight, open-source, enterprise-oriented **SMTP proxy** that:

| Need | Solution |
| --- | --- |
| Legacy apps / Zabbix / printers speak SMTP only | Accept SMTP (`AUTH PLAIN` / `LOGIN` / IP whitelist) |
| On-prem Exchange still uses EWS + NTLM/Basic/Kerberos | Translate SMTP → EWS via `exchangelib` |
| M365 killed Basic Auth; requires OAuth2/Graph | Translate SMTP → Microsoft Graph (MSAL client credentials) |
| DavMail is Java-heavy and fragile on auth parsing | Python async stack + **Smart Auth Sanitizer** |
| Ops need visibility & automation | FastAPI API-first + HTMX UI + Prometheus + webhooks |

**Stack (locked from blueprint):** Python 3.11+, `aiosmtpd`, FastAPI, HTMX/Alpine/Tailwind, SQLite WAL, `exchangelib` + MSAL.

**Deploy targets:** systemd installer, Docker/GHCR multi-arch, PyInstaller single binary.

## 7. EU Standards — Do You Need Them?

### Short answer

**No — you do not need formal EU certification to publish this as open-source, self-hosted software.**

### What that means in practice

| Topic | Required to publish OSS? | Worth doing anyway? |
| --- | --- | --- |
| CE marking / product conformity | No (software gateway, not a regulated hardware product) | N/A |
| GDPR “certification” | No mandatory cert for shipping code | **Yes, design for GDPR-friendly defaults** if EU users store message metadata/bodies |
| eIDAS / qualified trust services | No | No |
| NIS2 | Applies to *operators* of essential entities, not typically to the OSS author | Document secure deployment for those users |
| CRA (Cyber Resilience Act) | Evolving; open-source stewardship rules differ from commercial SaaS vendors | Follow secure-development basics (advisories, SBOM optional) |
| Accessibility (EN 301 549 / WCAG) | Not required for private OSS | Nice-to-have if targeting EU public sector |

### Practical GDPR-minded defaults (recommended, not a legal gate)

- Default bind `127.0.0.1`; no public exposure without explicit config.
- Configurable log retention; default short.
- Encrypt secrets at rest; redact credentials in UI/logs.
- No cloud telemetry by default.
- Document that the *operator* is the data controller for email content.

**Bottom line:** Ship freely. Treat EU compliance as **secure-by-default + privacy-respecting design**, not as a blocker or certification project unless you later sell a hosted SaaS in the EU.
