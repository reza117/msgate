## Summary

## User guide — queue / blast controls

All of these are set in **`msgate.env`** (or the process environment) and require a **service restart**. They are **not** in the Web UI yet.

| Variable | Default | Meaning |
| --- | --- | --- |
| `MSGATE_QUEUE_WORKERS` | `2` | Parallel outbound send threads (1–32) |
| `MSGATE_QUEUE_MAX_PENDING` | `5000` | Max queued/retrying messages; over → SMTP `452` |
| `MSGATE_CIRCUIT_FAILURE_THRESHOLD` | `5` | Consecutive send failures before circuit opens |
| `MSGATE_CIRCUIT_COOLDOWN_SECONDS` | `60` | Seconds before a half-open probe |
| `MSGATE_SMTP_REJECT_ON_CIRCUIT` | `true` | If true, circuit open → SMTP `451` |

**Behaviour**

1. SMTP **DATA** only writes the message to the DB and returns `250` (unless backpressure).
2. Workers claim rows and send via EWS; failures retry with backoff.
3. Too many failures → circuit **open** (workers pause; optional SMTP defer).
4. Queue too deep → SMTP **452** so Zabbix can retry later without losing the alert at the client if it buffers.

Metrics (Prometheus `/metrics`): `msgate_queue_pending`, `msgate_in_flight`, `msgate_smtp_deferred_total`, `msgate_circuit_open`, send latency gauges.

## User guide — capacity alerts

1. Open **Account** → set **Admin alert email** → enable email alerts → Save.
2. A yellow/red **banner** appears when queue depth, age, or circuit breaker is unhealthy.
3. On **critical**, msgate emails that address via Exchange (needs EWS credentials in Settings). Cooldown default 15 minutes.

Webhook URL field is reserved in config (`webhook_url`); use existing `MSGATE_WEBHOOK_URLS` for chat hooks until UI wiring is extended.

## User guide — SQLite vs Postgres

### Default: SQLite

No extra packages. Data file under `MSGATE_DATA_DIR` (default `/var/lib/msgate/msgate.db`). WAL + `busy_timeout` enabled.

**Stay on SQLite when:** single VM, modest Zabbix volume, queue drains after storms, no sustained high defer rate.

### Optional: Postgres

```bash
# install driver (once)
/opt/msgate/.venv/bin/pip install 'msgate[postgres]'
# or: pip install 'psycopg[binary]>=3.1'
```

In `msgate.env`:

```bash
MSGATE_DATABASE_URL=postgresql+psycopg://msgate:SECRET@127.0.0.1:5432/msgate
```

Then `systemctl restart msgate` (migrations run on start).

**Switch to Postgres when:** after a storm, queue age stays high **and** you see SMTP `452` / DB lock pressure; or you want stronger concurrent INSERT (SMTP) + UPDATE (workers) headroom on one host.

**Not required:** Redis / multi-node queue for Phase 5.5.

## Marketing / positioning

- **Absorb then drain** — Zabbix never waits on Exchange RTT.
- **Self-protecting** — circuit breaker and queue caps protect Exchange and disk.
- **Grow when needed** — same app, point `MSGATE_DATABASE_URL` at Postgres.

## Technical reference

| Piece | Role |
| --- | --- |
| `queue/service.accept_smtp` | Fast-accept enqueue + wake |
| `queue/worker.QueueWorker` | N threads, `claim_next`, circuit aware |
| `queue/circuit_breaker` | Open / half-open / closed |
| `ews/account_cache` | Per-thread Account reuse |
| `db/url.resolve_database_url` | `MSGATE_DATABASE_URL` or SQLite path |
| Optional extra | `msgate[postgres]` → `psycopg` |

Alembic uses the same URL (batch mode for SQLite only).
