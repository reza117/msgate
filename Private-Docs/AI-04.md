# AI-04 — Production TLS Negotiation (Adaptive)

> Status: **implemented** (2026-08-07)  
> Product: **msgate**  
> Related: Phase 1 live test against Wigner Exchange (`TLSv1` only)

---

## Problem (universal backends)

Different mail backends speak different TLS stacks:

| Backend | Typical TLS |
| --- | --- |
| Microsoft 365 / modern Exchange | TLS 1.2+ |
| Legacy on-prem Exchange | TLS 1.0 (e.g. Wigner) |
| Internal CA | Custom CA PEM required |

A one-off “force TLS 1.0” hack is not production-safe for a universal gateway.

---

## Solution

**Probe → select → cache → apply → re-probe on SSL failure**

1. Default `MSGATE_EWS_TLS_MODE=auto`
2. Probe ladder: `modern` → `legacy_tls1_1` → `legacy_tls1`
3. Cache winner in `data/tls_cache.json` (per host/port/mode/trust)
4. Install matching `requests` SSL adapter for exchangelib
5. On later SSL errors: invalidate cache, re-probe once, retry send

Trust is separate from protocol:

- Prefer `MSGATE_EWS_CA_FILE=/path/to/ca.pem`
- `MSGATE_EWS_TRUST_SELF_SIGNED=true` only as escape hatch

## GitHub Pages — User manual

### Environment

| Variable | Values | Default |
| --- | --- | --- |
| `MSGATE_EWS_TLS_MODE` | `auto`, `modern`, `legacy` | `auto` |
| `MSGATE_EWS_CA_FILE` | PEM path | unset |
| `MSGATE_EWS_TRUST_SELF_SIGNED` | `true`/`false` | `false` |

### Probe without sending mail

```bash
export MSGATE_EWS_URL="https://exchange.example.com/EWS/Exchange.asmx"
export MSGATE_EWS_TLS_MODE=auto
export MSGATE_EWS_TRUST_SELF_SIGNED=true   # or set CA_FILE
msgate tls-probe --apply-cache
```

### Legacy TLS / self-signed lab example

```bash
export MSGATE_EWS_URL="https://mail.example.com/EWS/Exchange.asmx"
export MSGATE_EWS_TLS_MODE=auto
export MSGATE_EWS_TRUST_SELF_SIGNED=true
msgate tls-probe --apply-cache
msgate serve --log-level DEBUG
```

Preferred in production: export your Exchange CA to a PEM file and set `MSGATE_EWS_CA_FILE`
(or Settings → CA file) instead of `trust_self_signed`.

## GitHub Pages — Technical

### Modules

| Module | Role |
| --- | --- |
| `msgate.tls.profiles` | Profile IDs + ladders |
| `msgate.tls.context` | `ssl.SSLContext` builder |
| `msgate.tls.probe` | Handshake-only probe |
| `msgate.tls.cache` | Memory + `data/tls_cache.json` |
| `msgate.tls.negotiate` | Orchestration for EWS |
| `msgate.tls.adapter` | exchangelib HTTP adapter |

### Self-healing

- Startup: `msgate serve` warms TLS before accepting SMTP
- Runtime: EWS send catches SSL-class failures → invalidate → re-negotiate → one retry
- After server upgrade to TLS 1.2, delete cache or wait for failure-driven re-probe; operators can force with `msgate tls-probe --apply-cache`

### Security posture

- Default tries **modern first**
- Legacy SECLEVEL only when modern handshake fails (auto) or mode=legacy
- Never auto-enables `trust_self_signed`; operator must set it or provide `CA_FILE`
