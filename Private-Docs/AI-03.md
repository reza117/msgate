## GitHub Pages — Marketing blurb (Phase 1)

**msgate** accepts standard SMTP from Zabbix, printers, and legacy apps, then delivers through on-premises **Exchange Web Services**.

Unlike fragile Java gateways, msgate includes a **Smart Auth Sanitizer** that correctly handles `DOMAIN\user`, `user@domain`, and plain usernames — the failure mode that breaks many DavMail + Zabbix setups.

## GitHub Pages — User manual (Phase 1)

### Run the gateway

```bash
cd msgate
source .venv/bin/activate
export MSGATE_EWS_URL="https://exchange.example.com/EWS/Exchange.asmx"
export MSGATE_EWS_AUTH_TYPE=ntlm          # or basic
export MSGATE_EWS_DOMAIN=WDC              # optional default domain
export MSGATE_EWS_TRUST_SELF_SIGNED=true  # if needed
export MSGATE_SMTP_BIND=127.0.0.1
export MSGATE_SMTP_PORT=1025
export MSGATE_SMTP_ALLOWED_IPS=127.0.0.1
msgate serve --log-level INFO
```

### Anonymous IP relay (optional)

If the client IP is in `MSGATE_SMTP_ALLOWED_IPS`, AUTH is optional. Then set service credentials:

```bash
export MSGATE_EWS_USERNAME='WDC\svc.msgate'
export MSGATE_EWS_PASSWORD='...'
```

### Test with swaks / Python

```bash
# AUTH with domain prefix (Zabbix-style)
swaks --to admin@example.com --from zabbix@example.com \
  --server 127.0.0.1 --port 1025 \
  --auth LOGIN --auth-user 'WDC\internal.wdc' --auth-password 'secret'
```

Point Zabbix SMTP media at `127.0.0.1:1025` with the same username format.

## GitHub Pages — Technical reference (Phase 1)

### Environment variables

| Variable | Purpose | Default |
| --- | --- | --- |
| `MSGATE_SMTP_BIND` | Listen address | `127.0.0.1` |
| `MSGATE_SMTP_PORT` | Listen port | `1025` |
| `MSGATE_SMTP_ALLOWED_IPS` | Comma-separated hosts/CIDRs | `127.0.0.1` |
| `MSGATE_EWS_URL` | EWS endpoint (required to serve) | — |
| `MSGATE_EWS_AUTH_TYPE` | `ntlm` or `basic` | `ntlm` |
| `MSGATE_EWS_DOMAIN` | Default Windows domain | — |
| `MSGATE_EWS_USERNAME` | Service account (anonymous relay) | — |
| `MSGATE_EWS_PASSWORD` | Service account password | — |
| `MSGATE_EWS_TRUST_SELF_SIGNED` | Disable TLS verify | `false` |

### Auth sanitizer rules

| Input | `ews_username` |
| --- | --- |
| `DOMAIN\user` | `DOMAIN\user` |
| `DOMAIN/user` | `DOMAIN\user` |
| `user@domain` | UPN kept |
| `user` + default domain | `DOMAIN\user` |

### Flow

```
SMTP client → aiosmtpd (AUTH PLAIN/LOGIN)
           → sanitize username
           → exchangelib Message.send_and_save()
           → Exchange EWS
```

## Known Phase 1 limits

- No durable queue/retry (Phase 2)
- No REST API / Web UI (Phases 2–3)
- No Microsoft Graph backend (Phase 4)
- Attachments: MIME parsed for text/html body; complex MIME attachment forwarding is minimal
- Peer AUTH state keyed by client IP (fine for local Zabbix; multi-session same IP is a later hardening item)
- **TLS:** production adaptive negotiation added in `AI-04.md` (`MSGATE_EWS_TLS_MODE=auto`)
